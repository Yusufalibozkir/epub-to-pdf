1. Executive Overview

1.1 Purpose & Scope

deluxe_epub_to_pdf.py is a local, single-script production pipeline that converts EPUB files into print-oriented A4 PDF interiors suitable for deluxe physical book editions. It targets large public-domain collected works (e.g., Delphi Classics, Project Gutenberg) and automates a strict professional book-production workflow.

The pipeline enforces: A4 trim, single-page PDF output, recto/verso start discipline, roman/Arabic pagination, running heads with collection/work title alternation, poetry/drama/cast-list normalization, functional vs. decorative image classification, promotional content removal, TOC page-number resolution, and rigorous PDF preflight QA with auto-fix capabilities.

2.3 Data Models

Five @dataclass classes organize all pipeline state:

Settings (~90 fields)

The complete typographic configuration — trim size, body font metrics, margin geometry, running head layout (6 variants), folio sizing, paragraph indent, blockquote margins, heading hierarchy (8 heading levels each with independent sizes and margins), TOC styling (4 levels), poetry verse block sizing, cast list layout, image policy (functional / keep-all / remove-all), front matter generation flags, rule pack paths, and pipeline behavior flags.

SpineDoc

Represents one EPUB spine item: index, item_id, name, href, raw bytes, extracted headings (up to 40), text sample (first 9,000 chars), text length, classification kind (one of 10 types), remove flag, major_title, current_division, poetry/drama/image boolean flags, and an AI confidence score.

TocEntry

Table of contents entry: hierarchical level (1–4), display title, target HTML anchor ID, and semantic kind (division / work / backmatter).

BuildLog

Complete audit trail: removed blocks, removed documents, kept/removed images, warnings, hard failures, AI decisions, title source, and counts for poetry blocks detected, cast sections detected, typographic fixes applied, and CSS auto-fix changes.

QAVerdict

Comprehensive quality-assurance state: page count, non-A4 pages, line spills, dark pages, blank page artifacts, header collisions, narrow columns, TOC warnings (page-number + duplicate), empty content pages, duplicate title pages, opener page warnings, work-description style warnings, first body folio warnings, OpenAI visual flags, text QA flags, AI rule suggestion file path, fonts seen, images seen, QA render paths. The has_blockers property aggregates all blocking conditions for --strict mode.

2.4 EPUB Scanning & Classification

The scanning phase reads EPUB spine items via EbookLib, then classifies each document through a two-tier system:

Tier 1: Heuristic Classification

heuristic_classify_doc() assigns each document a kind using the regex patterns. The priority chain:

  1. Promo detection — Gutenberg license text or short documents matching PROMO_PATTERNS
  2. Local TOC detection — "Contents" headings with low word count
  3. Backmatter — matching BACKMATTER_PATTERNS
  4. Collection divisions — matching COLLECTION_DIVISIONS
  5. Cast/drama — matching CAST_HEADINGS or flagged as containing drama
  6. Poetry — flagged by probe as poetry-containing
  7. Major works — H1 headings that aren't chapter-like, less than 100 chars
  8. Frontmatter — preface/introduction/foreword near the start
  9. Fallback: chapter — everything else

Tier 2: AI-Assisted Classification (optional)

apply_openai_book_plan() sends spine documents to OpenAI or DeepSeek in batches of 24, each with headings, text samples (3,500 chars), text length, and local heuristic flags. The AI returns structured JSON with kind, remove_document, major_title, current_division, and confidence scores. AI decisions only override when confidence ≥ 0.86 for removals.

2.6 CSS Generation Engine

css_text() generates the complete print stylesheet (~400 lines of CSS) driven entirely by the Settings dataclass. Key features:

  • @page rules: title, front (roman folios), body (Arabic folios), opener (no folios), nofolio (blank pages), :blank (true blank pages)
  • Running head layouts: Six variants — right_title_full_rule (collection title verso, current work recto + full-width vector rule), centered_single_rule, dual_full_rule, alternating, plus two split-rule varieties
  • TOC rendering: Two-pass system — first pass uses CSS target-counter(attr(href), page) with leader dots; second pass uses explicit resolved page numbers with CSS Grid layout for precise alignment
  • Hard normalization: Aggressive !important overrides against ebook CSS (max-width: none, width: auto) on all body elements
  • Verse styling: Max-width constraint, hanging indents via negative text-indent + padding-left, ragged-right alignment, pre-wrap white-space
  • Cast list styling: Constrained max-width, left-aligned
  • Work description styling: Italic, smaller font (body_size_pt − 1pt), no indent, bottom margin
  • Heading hierarchy: 8 distinct heading levels (major-work, collection-division, backmatter-opener, subdivision, part-heading, chapter-section-heading, h3, minor-heading) each with independent font size, margins, and letter-spacing

2.7 PDF Rendering & Optimization

The rendering pipeline operates in distinct phases:

  1. write_build(): Writes book.html and style.css to the build directory
  2. render_pdf(): Calls WeasyPrint's HTML.write_pdf() with the CSS stylesheet
  3. resolve_toc_page_numbers(): Opens the rendered PDF with PyMuPDF, extracts internal link destinations from TOC pages, maps target IDs to physical page numbers
  4. Second render pass: If TOC page numbers were resolved, re-renders HTML with explicit page numbers in a CSS Grid layout
  5. subset_pdf(): For sample mode, extracts first N pages using PyMuPDF
  6. draw_vector_runner_rules(): Post-render vector drawing — uses PyMuPDF's Shape API to draw clean stroke-only horizontal lines at the configured runner_rule_y_mm position, only on pages that have running-head text
  7. optimize_pdf(): pikepdf compression, object stream generation, and linearization for web-fast viewing

3. AI Integration

3.1 Providers & Models

The pipeline supports two AI providers via the --ai-provider flag:

  • OpenAI — default provider. Uses responses.create() with structured JSON schema for book structure planning and visual QA. Default model: gpt-5.4-mini.
  • DeepSeek — uses chat.completions.create() with JSON mode. Default model: deepseek-chat. Runs text QA after local deterministic QA completes.
  • none — disables all AI features; purely deterministic pipeline.

3.2 Structure Planning

apply_openai_book_plan() sends spine documents in batches of 24. Each batch includes: document index, href, first 20 extracted headings, text sample (3,500 characters), text length, and local heuristic flags (contains_poetry, contains_drama, contains_images).

The AI returns structured JSON classifying each document as one of: frontmatter, division, major_work, chapter, poetry, play, backmatter, promo, local_toc, or unknown. It also returns a remove_document flag (only applied at ≥86% confidence) and a major_title string for work-level heading assignment.

3.3 Image Classification

ai_image_decision() sends image src + surrounding context (3,000 characters of caption and nearby text) to the AI for classification as authorial/functional vs. publisher-added plate. The decision is only applied at ≥70% confidence. The should_keep_image() function implements a multi-tier decision:

  1. If image_policy is "keep-all" → keep
  2. If image_policy is "remove-all" → remove
  3. If plate context is detected without functional context → remove
  4. If AI is available, consult it with confidence threshold
  5. If functional context is detected → keep
  6. If "cover" or "title" in src with short context → remove

3.4 Visual & Text QA

Visual QA (OpenAI vision)

Renders up to --openai-qa-pages (default 10) pages as JPEG images, base64-encodes them, and sends them to the vision model with a 9-category inspection prompt: body justification, paragraph rhythm, chapter/title placement, running heads/rules, folios, TOC, image cleanup, poetry/drama, and ebook artifacts. Returns PASS/FAIL with page-specific findings.

Text QA (DeepSeek or OpenAI)

Sends extracted PDF text (first 28 pages, 60,000 characters) + local QA reports + settings excerpt to the text model for structural review. The model can generate regex rule suggestions stored as .review.yaml files using only the 13 known rule-pack keys. These files must be manually reviewed before loading.

4. Configuration & Auto-Fix

4.1 Three-Layer Override Precedence

Settings resolve in this exact order:

  1. Built-in defaults — hardcoded in the Settings dataclass
  2. Config file — YAML or JSON via --config; unknown keys are warned and ignored
  3. CLI flags — ~25 explicit command-line overrides (e.g., --body-size, --line-height, --margin-side)

write_default_config generates a complete editable YAML config with all defaults and a comment header explaining the override order.

4.2 Rule Pack System

External YAML files in the rules/ directory can extend any of the 13 built-in regex patterns. The bundled generic_epub.yaml adds:

  • 5 promo patterns ("free sample", "about delphi classics", etc.)
  • 4 plate caption patterns ("cover image", "title card", "decorative plate", "photogravure")
  • 3 functional image clues ("genealogical table", "family tree", "ground plan")
  • 3 publisher image source clues ("frontmatter", "titlepage", "halftitle")

Each pattern is validated as a valid regex before merging. AI-generated suggestions are written as {provider}_rule_suggestions.review.yaml files.

5. Enhancement Roadmap

5.1 Architectural Improvements

AdditionRationale
Modular package split Split 3,620-line monolith into pipeline/ with ~10 modules (~300–500 lines each). Preserves single-command experience via __main__.py while gaining testability, maintainability, and contributor accessibility.
Pipeline as DAG Model each transformation as a directed acyclic graph node. Enables: (a) caching intermediate results, (b) parallel document processing, (c) selective re-execution when only one stage changes.
Caching layer Save cleaned HTML per document keyed by content hash. When tweaking --line-height or margins, the entire scan/classify/clean phase is skipped — only CSS + render reruns. Saves minutes per iteration on large collected works.
Plugin system Beyond regex rule packs: register custom Python cleaners, classifiers, and post-processors via a plugin hook system without modifying core code.

5.2 Missing Typographic Features

FeatureHow It Fits the "Deluxe" Vision
Drop caps / initial caps Detect first paragraph after chapter headings; wrap first letter in <span class="drop-cap"> with CSS initial-letter: 3. A defining feature of deluxe print editions.
Small caps normalization Distinguish ALL-CAPS acronyms from semantic small caps (AM/PM, BC/AD, abbreviations). Convert to font-variant: small-caps. Critical for scholarly typography.
Ligature control Add configurable font-variant-ligatures with per-element overrides. EB Garamond has rich ligature sets that professional typography controls deliberately.
True footnote placement Collect footnote bodies, place at page bottom with rule separator using WeasyPrint float: footnote. Currently footnote bodies are lost or become inline text.
Post-render widow/orphan check CSS widows:2; orphans:2 is advisory — real rendering often produces widows anyway. A post-render analysis catches and flags actual widow/orphan occurrences by page.
River detection Image-processing on rendered PNG pages: detect vertical white-space gaps in justified text via connected-component analysis. Rivers are a hallmark of poor justification and are explicitly mentioned in the production prompt.
Page balance check Detect chapters where the last page carries fewer than 4–5 lines. Professional typesetters avoid "widow pages" with only 1–2 lines.
Table intelligence Detect wide tables, optionally rotate to landscape on their own page. Auto-fit column widths. Handle multi-page tables with repeated headers. Essential for genealogical tables and chronologies.
Margin notes / sidenotes Detect note-like short paragraphs and convert to CSS @left-middle or float-based sidenotes. Common in annotated classics.
Multi-column layouts Support 2-column mode for indices, bibliographies, and chronologies. Configurable per-document-kind.

6. Conclusion & Priority Matrix

The deluxe_epub_to_pdf.py pipeline is already a remarkably capable and well-engineered tool. It handles the hardest problems in EPUB-to-print conversion — structural classification of malformed public-domain EPUBs, promotional content removal, image triage, poetry/drama normalization, and rigorous QA — with a level of thoroughness that surpasses most commercial and open-source alternatives.
